# Правило: faceless-графика (инфографика, перечисления, цифры)

Faceless-момент — кусок ролика без лица: цифры, метрики, список шагов, «до/после». Задача куска —
за 2–3 секунды вбить в голову один смысл. Плохой пример: `bad_examples/01_example_text.mp4`
(5.4–27.0 c, проект example-app) и кадр `bad_examples/05_bioage_faceless_before.jpg`: мелкий системный шрифт, одинаковые белые карточки, всё появляется разом и стоит,
субтитры дублируют то, что уже написано, цифры не играют. Хороший: `good_examples/01_faceless_kinetic.mp4` и `good_examples/05_bioage_faceless_after.jpg` (та же сцена после правки: тёмный фон с зерном, крупные цифры Inter Tight, один текстовый слой).

Ещё один плохой пример: `bad_examples/06_static_cards_system_font.png` (Biological age, Apple Watch): белые одинаковые
карточки с мелкими цифрами системным шрифтом, без иерархии и движения. После правки: `good_examples/06_kinetic_cards_designed.png`.
Каждый экран проходит дизайн-шаг `rules/design-pass.md` (бриф, 3 превью, `scripts/design_lint.py`) до рендера видео.

## Обязательно для любой опции

1. **Шрифт.** Только гротеск с жирными начертаниями: Inter Tight 800–900 (по умолчанию), Manrope 800,
   Space Grotesk 700. Цифры — 900, `tabular-nums`, трекинг −3…−6 %. Системные шрифты и Arial запрещены.
2. **Иерархия размеров (кадр 1080×1920):** ключевая цифра 250–600 px, заголовок 110–170 px,
   подпись/лейбл 32–40 px капсом с трекингом +15 %. Между уровнями ≥ ×2.5. Ничего мельче 32 px.
3. **Один смысл на кадр.** Если на экране крупно то же, что говорит диктор, субтитры прячем.
   Один текстовый слой за раз.
4. **Всё по слову.** Каждый элемент появляется в момент, когда диктор его называет
   (тайминги из whisper word timestamps, допуск ±0.1 c). Ничего не стоит статично дольше 1.5 c:
   счётчик, рисующийся график, лёгкий зум фона.
5. **Движение:** вход 0.3–0.5 c c easeOutBack (небольшой перелёт), выход 0.25 c easeIn. Без вращений,
   без «вылета по буквам» на длинных фразах.
6. **Цвет:** тёмный фон (#0B0E13) + 1 акцент бренда (`accent` в конфиге проекта) + 1 вторичный для «хорошо»
   (`good`, по умолчанию #3DDC97). Активный пункт — акцент, пройденные — 40 % прозрачности. Зерно 5–8 % поверх, чтобы не было «плоского PowerPoint».
7. **Безопасные зоны:** верх 220 px и низ 380 px (UI Reels/TikTok) — без ключевого текста.
8. **Цифры считают**, а не появляются: 0→31 за 0.7 c; рост возраста 57→61 — тиканьем.
9. **Антиалиасинг и чистые края.** Графику рендерим из HTML в полном разрешении ролика (`render_html.py --size 1440x2560`,
   это device scale ×2), без апскейла готового видео, кодируем `crf ≤ 18`. На кропе ×2 у букв, цифр, иконок
   и скруглений не должно быть ступенек. У текста нет `stroke`, белых обводок и ореольных `text-shadow`
   (допустима мягкая тень для читаемости над видео).
10. **Иконка и логотип бренда** — только оригинальная иконка из App Store со скруглением 22.37 %, без обводки
    (как её взять: `rules/end-card.md`). Перерисованные или вырезанные со скрина иконки запрещены.

## Три опции (выбирать под сценарий)

### A. Kinetic Data — метрики и цифры (по умолчанию)
Тёмный фон, стеклянные карточки, огромная цифра, рисующийся спарклайн, активная карточка с
оранжевой обводкой и свечением. Подходит для «устройство меряет X, Y, Z», «твой показатель 61», «+5 к норме».
Шаблон: `templates/faceless_kinetic/scene.html`, все тексты/цифры/цвета/тайминги в `projects/<проект>/faceless.json`
(`render_html.py ... --cfg projects/<проект>/faceless.json`). Пример: `good_examples/01_faceless_kinetic.mp4`.

### B. Big Type — одно слово на весь экран
Каждое слово перечисления занимает экран целиком (200–320 px, 900), смена по слову диктора
жёстким катом или маской-шторкой 0.15 c. Фон — плашка цвета бренда, текст тёмный; на последнем
слове инверсия. Подходит для коротких перечислений из 3–4 слов («Movement. Nutrition. Sleep.»)
и для хука в первые 2 секунды.

### C. UI-in-hand — данные внутри экрана приложения
Кадр телефона (реальный скрин приложения) на размытом фоне сцены; нужная цифра «вылетает» из
экрана наружу крупной плашкой (×3 к размеру на экране) с тенью; стрелка/обводка указывает
источник. Подходит для «приложение показало мне X», «было → стало»: зритель видит, что это продукт, а не графика.

## Перечисления внутри UGC (говорящая голова)
Когда в UGC человек перечисляет (три функции продукта, три причины проблемы, три шага плана) — поверх видео делаем графику опции A или B, а не только субтитры:
- плашки появляются по слову, стопкой в нижней трети на месте субтитров (лицо не перекрывать!), нумерация 01/02/03, не длиннее 3 слов на плашку;
- для «проблем» — красноватый акцент и иконка ✕/↓, для «что делать» — зелёный ✓;
- обычные субтитры в эти секунды убираем (одно текстовое поле на кадр);
- в сценарии такие места помечаем тегом `[ENUM: пункт1 | пункт2 | пункт3]`, см. `rules/ugc-script-format.md`.
