# Правило: дизайн-шаг на каждый экран графики

Утверждено Дмитрием 12.11.2026. Касается любого экрана с текстом или графикой: faceless-сцены, плашки ENUM,
BIG/DELTA, субтитры, эндкарта. Экран надо **задизайнить**, а не собрать «как получилось».

Плохой пример: `bad_examples/06_static_cards_system_font.png` (Example App, Biological age, Apple Watch).
Белые одинаковые карточки «Cardio fitness 36 / HRV 43 / Resting HR 60», системный шрифт, мелкие цифры,
нет иерархии, всё стоит без движения, фон плоский, подпись внизу дублирует диктора. Выглядит как PowerPoint.
Хороший пример: `good_examples/06_kinetic_cards_designed.png` (тот же экран после правки).
Тёмный фон с зерном, цифры Inter Tight 900 в 2.5 раза крупнее подписи, карточки влетают по слову диктора,
активная подсвечена акцентом, спарклайн рисуется, итог крупным заголовком.

## Шаги (на каждый экран, до рендера видео)
1. **Бриф экрана** (`<работа>/design/<экран>.md`, 5–8 строк):
   - один смысл экрана одной фразой;
   - главный элемент (цифра, слово, иконка) и что второстепенно;
   - иерархия размеров в px при 1080: главный элемент, заголовок, подпись (между уровнями не меньше ×2.5);
   - вход, движение на экране, выход (по каким словам диктора, тайминги из whisper);
   - опция A, B или C из `rules/faceless-graphics.md`, цвета (фон, акцент, «хорошо»).
2. **Три превью-кадра**: вход, пик, выход.
   `python3 scripts/render_html.py <шаблон> <words.json> <t0> <t1> <работа>/design/<экран> --preview <tвход>,<tпик>,<tвыход> --cfg <cfg>`
3. **Линтер**: `python3 scripts/design_lint.py <шаблон> <words.json> <t0> <t1> --cfg <cfg>`. Код выхода должен быть 0.
4. **Самопроверка по рубрике** (глазами, по превью):
   - [ ] шрифт из списка (Inter Tight, Inter, Manrope, Space Grotesk), системных нет;
   - [ ] между уровнями иерархии не меньше ×2.5, ничего мельче 32 px при 1080;
   - [ ] один смысл и один текстовый слой: субтитры не дублируют графику;
   - [ ] ничего не стоит статично дольше 1.5 с: счётчик, рисующаяся линия, лёгкий зум;
   - [ ] живой фон (зерно, свечение, видео), не «плоский PowerPoint»;
   - [ ] безопасные зоны: верх 220 px и низ 380 px кадра 1080×1920 без ключевого текста;
   - [ ] антиалиасинг (рендер в 1440×2560 или 1080×1920 из HTML), у текста нет обводок;
   - [ ] иконка бренда только из App Store (`rules/end-card.md`).
5. Не прошло — правим бриф или шаблон и повторяем 2–4. Только после этого рендерим видео.
   Бриф, превью и вывод линтера кладём рядом с работой (`<работа>/design/`).

## Запрет короткого пути
Любой текст на видео делается только HTML-шаблоном и `scripts/render_html.py`.
Нельзя: `ffmpeg drawtext`, фильтры `subtitles=` / `ass=` с системным шрифтом, `PIL ImageDraw.text`, текст, вшитый генерацией.
Сборщик `scripts/ugc_build.py` падает, если в команде ffmpeg есть drawtext, subtitles или ass (`scripts/text_guard.py`).
Проверить свои скрипты: `python3 scripts/text_guard.py <папка>`.
